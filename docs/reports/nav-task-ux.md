## 二、完成的内容

### 1. 侧边栏重新整理

- **七个分组，按要求的顺序：** 概览 → 工作与事务（工作、业务、行政事务、重要截止日期、项目、看板、甘特图、目标）→ 任务（全部任务、四象限矩阵、已排程任务、回收站）→ 个人成长与生活（成长、学习、健身、技能、个人生活、日历、角色、经验值、奖励等）→ 资料与记录（文件）→ 财务（资产总览、账户）→ 系统与自动化（自动化规则、通知、设置）。
- **展开和收起：** 每个分组都可以展开或收起，选择保存在浏览器里，刷新后保持。默认全部展开；打开某个分组里的页面时，该分组会自动展开。
- **「目标」：** 原来指向占位页，但成长目标（M8）其实已经做好，现在会直接打开「成长」页面里的目标区域。
- **其他整理：** 「行政任务」改名为「行政事务」；「设置」移到「系统与自动化」分组。还没开发的模块仍然显示，并标出所属阶段。
- **检查范围：** 桌面端和手机抽屉式导航都检查过（见第六节截图）。

### 2. 项目与领域联动

- **新建任务：** 在项目里新建的任务，自动使用项目的领域；用户自己选的领域，或明确选择「无领域」，都会保留。这条规则在服务器端统一执行，所有新建任务的方式都适用。
- **移入项目：** 把任务移到项目时，只有任务还没有领域，才会使用项目的领域；已有的领域永远不会被覆盖，之后编辑其他字段也不会改变领域。
- **未分配项目的任务：** 「全部项目」页面新增这个区域。任务可以拖到项目卡片上，也可以用「移到项目」菜单（适合键盘和触屏）；两种方式都只是修改原任务的所属项目，不会重建任务。

### 3. 全部任务页面

- **直接编辑：** 每个任务下方有一行属性，可以直接修改状态、优先级、领域、项目、开始日期和截止日期。修改先在界面上立即显示，再保存到服务器；服务器拒绝时会恢复原值并提示。菜单里的选项只在打开时才生成，任务很多时页面也不会变重。
- **子任务：** 点击箭头可以展开或收起子任务；展开后的子任务同样可以直接编辑和完成。点击任务标题仍然会打开完整的编辑面板（这是为了保留原有的打开方式，有意这样设计）。
- **开始日期默认今天：** 只用于在任务列表里用快速添加新建的任务。服务器、编辑操作、已有任务、自动化和重复任务都不受影响。
- **父任务与子任务的一致性：** 完成父任务时，可以同时完成未完成的子任务，默认勾选，日期相同；已取消的子任务不会被改变。完成最后一个子任务**不会**自动完成父任务，以免出现意料之外的改动。父任务上的 `x/y` 会实时显示子任务完成进度。

### 4. 完成日期确认

- **哪些操作会弹出确认窗口：** 圆形勾选框、`x` 快捷键、详情面板的「完成」、详情面板和直接编辑里的状态菜单、看板的拖动或「移到」菜单。
- **日期规则：** 默认今天；可以选择以前的日期，并有「昨天」快捷按钮；不能选择未来日期，服务器也会拒绝。
- **取消：** 取消或按 Esc，任务状态不变。
- **已完成的任务：** 不会被重新记录，原来的完成时间保持不变。
- **补录的时间：** 补录到以前的日期时，会记为当地时间那一天的中午，这样在所有视图里都落在你选的那一天。

## 四、文件模块分析（只做分析，本轮不开发）

### 1. 原本要解决什么问题

产品文档里**没有**文件模块的详细设计，以下只陈述能找到的依据，不推测原始设计：

- 路线图把它列为第 2 阶段的最后一项：“… → skill XP → **notes & documents**”。
- 最初的导航把「文件」放在「行政事务」分组里，和「行政任务」「重要截止日期」并列（路由 `/admin/documents`，第 2 阶段）。
- JSON 导出的决策记录（ADR 0025）明确写着：上传的文件还不存在，所以导出里没有附件。

由此能确认的只有：它被设想为**和行政事务相关的资料**，与笔记一起规划在第 2 阶段末尾。例如合同、发票、证件、报税材料、保单等需要保存并按期限处理的文件。具体的使用场景、数据结构和存储方式**从未设计过**。

### 2. 目前的实际实现

- **已实现：** 无。
- **占位页面：** 只有导航项「文件」（现在位于「资料与记录」），打开后是通用的「规划中」说明页。
- **完全没有开发：** 数据表、上传、存储、下载、预览、搜索、和任务或项目的关联、备份和导出，全部没有。

### 3. 应该和其他模块怎样关联

按产品原则“记录一次，到处可用”：

- **任务、项目、目标**：一份文件可以挂到某个任务（例如报税任务挂上发票）、项目（项目资料）或目标（学习证书），**不复制文件**，只是建立关联。
- **行政事务**：最主要的使用场景。文件本身可以带有效期，例如证件到期、合同续签，到期前生成提醒或任务，再和「重要截止日期」联动。
- **学习**：课程资料、证书；等学习和技能模块做好后，再关联到技能。
- **工作**：项目交付物、会议纪要（与将来的笔记重叠）。

### 4. 建议

**建议做成任务和项目的附件，加上一个统一的「资料库」视图，而不是独立的文件管理中心。** 理由：

- 和现有设计一致：系统的每种视图都是同一批数据的不同查询（任务行同时出现在列表、矩阵、看板、甘特图里）。「资料库」只是把所有文件集中显示的一个视图，文件本身通过关联属于任务、项目或目标。
- 用户真正的问题是“这件事的材料在哪里”，而不是再管理一棵文件夹树；独立的文件中心会和电脑本地或网盘里的文件夹重复。
- 第一步可以很小：先只支持「链接或路径加说明」（指向网盘或本地文件），不上传二进制文件。这样不会带来存储、备份体积和隐私方面的新风险，也能马上用起来。
- 真正上传文件之前，需要先决定：存放位置（Docker 数据卷还是对象存储）、大小限制、备份（`pg_dump` 不包含磁盘上的文件，需要另外备份）、JSON 导出中怎样包含或引用文件，以及与「重要截止日期」的提醒联动。

以上是建议，最终是否实施、按什么顺序实施，等你决定后再按整体计划进行。

## 七、已知限制

- **完成最后一个子任务不会自动完成父任务**（是有意的设计）；完成父任务时可以选择同时完成子任务。
- **补录的完成日期记为那一天的中午（当地时间）。** 对于设有截止时间的任务，中午可能晚于截止时间；目前不能选择具体时刻。
- **补录完成时获得的经验值记在补录当天**，而不是所选的完成日期。
- **新任务开始日期默认今天**，所以截止日期不能早于今天；要补录截止日期已经过去的任务，需要先修改开始日期。
- **项目页面的拖动只支持「未分配项目的任务」**。已在某个项目里的任务要换项目，请用直接编辑里的项目菜单。
- 侧边栏的展开状态保存在当前浏览器里，不会在不同设备之间同步。
- 手机上每个任务的属性行会占两到三行，任务列表比原来长。
- 截图里的日期格式 `11/01/2026` 来自测试浏览器的英文环境；中文浏览器会显示为 `2026/11/01`。
- 学习、技能、日历、已排程任务、文件、健身和统计分析都还只是占位页面（见第三节）。
