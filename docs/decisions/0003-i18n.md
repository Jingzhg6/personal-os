# 0003 — i18n: zh-CN source catalogue, no locale in URLs

**Decision.**

- next-intl without i18n routing. The locale comes from the user's settings (DB), falling back
  to the `NEXT_LOCALE` cookie, then `zh-CN`. URLs are language-neutral (`/tasks`, not `/zh-CN/tasks`).
- zh-CN is the source catalogue and is always complete. `en` and `fr` are structurally
  supported: missing keys fall back to zh-CN at runtime, and `pnpm i18n:check` reports coverage.
- Translation files are split by namespace (`messages/<locale>/<namespace>.json`) so each
  module's strings stay together.
- Language names are shown as endonyms (简体中文 / English / Français) and are not translated.
- Literal UI text in JSX is a lint error.

**Why no URL prefix.** It is a private, authenticated app: there is no SEO need, and the
language is a user preference, not a property of the page. Switching language must not
change any URL or data.
